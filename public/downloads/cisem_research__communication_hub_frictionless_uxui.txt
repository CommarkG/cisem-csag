1. INTRODUCTION & INDUSTRY CONTEXT
--------------------------------------------------------------------------------
Topic Overview:
Building an integrated Communication Hub requires unifying multi-channel messaging (WhatsApp, email, internal system comments, client feedback notes) with a "Frictionless UX/UI" design system that maximizes text density, enforces single-row placement rules, and guarantees visual consistency across all viewports.

Needs & Business Pains:
Operators and sales managers waste significant time switching between disparate communication tools (WhatsApp web, email client, CRM comments, PDF feedback). Traditional enterprise UIs suffer from bloated vertical padding, multi-row title sprawl, inconsistent icon usage, and broken RTL (Hebrew/Arabic) alignment.

Challenges:
- Unified Conversation Stream: Aggregating messages from external channels (Green API WhatsApp, SMTP email, system alerts) into a single, real-time client conversation timeline.
- Single-Row Layout Enforcement: Placing titles, status indicators, user avatars, and action controls on a single horizontal row without wrapping or wasting vertical screen real estate.
- Sibling Representation Consistency: Ensuring sibling buttons and list items inside the same horizontal group maintain identical visual weight (icon + label pattern).

Common Gaps & Mistakes:
- Splitting related title info across 3 vertical rows, forcing users to scroll excessively.
- Mixing plain text buttons next to icon-only buttons in the same toolbar.
- Hardcoding static pixel offsets for dynamic RTL UI layouts instead of calculated flex container bounds.

Common Solutions Available & What We Can Do Better:
- Standard Solution: Generic chat widget embedded in a side panel.
- What We Can Do Better: CISEM UX/UI Law: Single-Row Placement Rule (combine greetings, status indicators, and controls into a single dense row) + Sibling Consistency Rule + Multi-Channel Communication Engine (Green API WhatsApp + system comments + real-time status updates).


2. PLATFORM CONTEXT & OPTIMAL USAGE
--------------------------------------------------------------------------------
What Exists in Our Platform:
- Layout Laws (GEMINI.md Section 7 & AGENTS.md Rules 21-22): Single-Line Placement Rule (7.1/21) and Sibling Representation Consistency Rule (7.2/22).
- Dynamic Navigation (src/components/dynamic_menu.tsx): Unified top bar with responsive menu items and dark/light mode switcher.
- Communication Protocols (backend/src/backend/main.py): WhatsApp / messaging webhooks and status library tables.

Best Way to Use It:
- Structure all communication stream items, project headers, and table rows to follow the Single-Line Placement Rule.
- Ensure every button in a action bar carries both an icon and text label (Sibling Consistency Rule).
- Use dynamic flex containers with dir="rtl" support for Hebrew/Arabic UI alignment without static pixel hacks.


3. BACKEND SENSITIVE POINTS NEEDING ATTENTION
--------------------------------------------------------------------------------
- Asynchronous Webhook Processing: Inbound WhatsApp / email webhooks must return 200 OK immediately and process message parsing asynchronously to prevent third-party gateway timeouts.
- Conversation Tenant Isolation: Ensure all message logs, communication threads, and attachment URLs enforce tenant_id = current_tenant_id() in Postgres RLS policies.
- Real-Time Websocket / SSE Streaming: Use stateless Server-Sent Events (SSE) or WebSockets to stream incoming messages directly to the frontend without polling.


4. FRONTEND SENSITIVE POINTS NEEDING ATTENTION
--------------------------------------------------------------------------------
- Strict Single-Row Layouts: Ensure headers, greetings, and status chips never wrap onto secondary rows on standard desktop viewports (>=1280px).
- Sibling Consistency Audits: Mechanically audit toolbar groups to verify all siblings share uniform representation (e.g. icon + text label).
- Glassmorphism & Micro-Animations: Use modern CSS backdrop filters, smooth hover transitions, and subtle pulse animations for active messaging indicators.
